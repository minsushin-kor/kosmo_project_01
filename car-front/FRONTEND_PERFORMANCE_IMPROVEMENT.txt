  발생하던 불필요한 렌더링을 줄였다.
- 검색, 필터, 상태 변경 시 테이블 렌더링 부담을 줄였다.


4-3. MessageDropdown 초기 로딩 개선

- 메시지 버튼과 실제 채팅 패널을 분리하였다.

- 채팅방 목록과 채팅 상세 기능은 사용자가 메시지 버튼을
  처음 눌렀을 때 동적으로 불러온다.

지연 로딩 대상
- 채팅방 목록
- 메시지 목록
- 이미지 전송
- 이모지 기능
- 자동 스크롤

- 연속 메시지 시간 계산

다음 이벤트의 역할을 분리하였다.

유지된 기능

4-6. 관리자 대시보드 병렬 호출 적용

4-7. localStorage 초기 로딩 개선

다음 화면의 초기 상태 생성 방식을 개선하였다.
- 최종 거래 관리
- 딜러 매물 관리

개선 방식
- 컴포넌트 렌더링마다 localStorage를 읽지 않는다.
- useState 초기화 함수를 이용해 최초 상태 생성 시 한 번만 읽는다.
- 불필요한 JSON.parse 반복을 줄였다.


4-8. DealerPage 상태 및 계산 개선

- 딜러 매물 탭 상태 처리 오류를 수정하였다.
- 리뷰 계산 구조를 정리하였다.
- 렌더링 중 반복 계산과 상태 불일치 가능성을 줄였다.


4-9. 회원 경매 최종 거래 계산 개선

- 경매 낙찰 및 최종 거래 데이터 계산 구조를 정리하였다.
- 동일 데이터의 중복 계산을 줄였다.
- 잘못된 거래 결과가 표시될 가능성을 줄였다.


4-10. 임시 ID 생성 방식 개선

기존
- Date.now()

변경
- crypto.randomUUID()

개선 효과

4-11. 불필요한 useMemo 제거

다음 위치에서 불필요한 useMemo를 제거하였다.
- RightSidebar
- MyPage 찜 목록

개선 이유
- 단순 계산에 useMemo를 사용하면 계산 비용보다
  의존성 관리와 메모이제이션 비용이 더 커질 수 있다.
- Hook 구조를 단순화하고 React Compiler 경고 가능성을 줄였다.


4-12. 라우트 Lazy Loading 적용

수정 파일
- src/data/routeData.jsx
- src/App.jsx

적용 내용

- App.jsx에 Suspense 로딩 화면을 추가하였다.
- 관리자, 회사, 딜러, 회원 페이지를 개별 청크로 분리하였다.

유지한 항목

- 라우트 ID
- allowedRoles
- ProtectedRoute
- churnType 전달 구조

추가 파일

적용 내용

- 페이지 다시 불러오기 버튼을 추가하였다.
- 홈으로 이동 버튼을 추가하였다.

개선 효과
- 배포 직후 캐시 불일치나 네트워크 문제로
  페이지 청크를 가져오지 못해도 복구할 수 있다.


4-14. 선택적 Route Prefetch 적용

추가 파일
- src/data/routeLoaders.js

적용 위치
- routeData.jsx
- Header.jsx
- NotificationDropdown.jsx

동작 방식
- 메뉴에 마우스를 올릴 때 대상 페이지 청크를 미리 불러온다.
- 키보드 포커스 시 미리 불러온다.
- 모바일 터치 시작 시 미리 불러온다.
- 이미 불러온 경로는 Set으로 관리해 중복 요청하지 않는다.

개선 효과
- 로그인 직후 모든 페이지를 한꺼번에 불러오지 않는다.
- 초기 번들 크기를 유지한다.
- 실제 메뉴를 클릭했을 때 첫 이동 체감 속도를 줄인다.


4-15. NotificationDropdown 이벤트 개선

- 알림창이 닫혀 있을 때는 외부 클릭 이벤트를 등록하지 않는다.
- 알림창이 열린 동안에만 mousedown 및 keydown 이벤트를 등록한다.
- 알림창이 닫히면 이벤트를 즉시 정리한다.
- ESC 키 닫기를 지원한다.
- 알림 링크에도 Route Prefetch를 적용하였다.


4-16. RightSidebar 및 홈 목록 개선

점검 대상
- 최근 본 차량
- 추천 차량
- 인기 검색 조건
- 차량 필터 및 정렬
- 페이지네이션

개선 내용
- 최근 본 차량 변경 시에만 관련 계산을 갱신한다.
- 추천 차량 계산 결과를 필요한 의존성이 변경될 때만 다시 계산한다.
- 사이드바 차량 항목에 memo를 적용한다.
- 역할별 차량 목록 계산을 분리한다.
- 필터 과정의 문자열 및 숫자 변환 반복을 줄인다.
- 검색 결과가 줄어 현재 페이지가 범위를 벗어나도 빈 화면이 나오지 않도록 처리한다.

6. 성능 개선 원칙
==================================================

1. useMemo와 useCallback은 실제 계산 또는 렌더링 비용이 큰 경우에만 사용한다.

2. 닫혀 있거나 사용하지 않는 UI는 document 및 window 이벤트를 등록하지 않는다.

3. 서로 독립적인 API 요청은 가능한 경우 병렬 처리한다.

4. localStorage JSON 파싱은 최초 초기화 또는 명확한 데이터 변경 시점에만 수행한다.

5. 페이지 단위 기능은 Lazy Loading을 사용한다.

6. 사용 가능성이 높은 메뉴만 선택적으로 Prefetch한다.

7. chunkSizeWarningLimit를 높여 경고만 숨기는 방식은 사용하지 않는다.

8. manualChunks는 실제 번들 분석 결과가 필요한 경우에만 적용한다.

9. 기능 수정 이후 다음 검사를 함께 진행한다.
- npm run lint
- npm run build
- 역할별 주요 화면 수동 테스트

10. 다음 문제도 성능 개선 시 함께 점검한다.
- 무한 렌더링
- 반복 요청
- 이벤트 리스너 정리 누락
- 타이머 정리 누락
- 잘못된 이미지 경로
- 중복 서버 실행
- 과도한 CPU 사용
- 과도한 메모리 사용
